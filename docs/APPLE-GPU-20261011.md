The current source contains three targeted graphics backports on the existing
AnyPS5 pin, `c963432db05f8b35c62e212b3a36494501522fe2`. The complete eleven-patch
stack applies to the pristine pin, matches the checked-out source and reverses
exactly across 235 paths. Six fresh native ARM64 CPU suites pass, including
355 canonical and 538 extended ordered interpolation cases, plus 24 LDS compiler profiles. All
24 generated LDS modules pass independent Vulkan 1.1 SPIR-V validation. The
fresh local 47-library Windows build passes 54 host cases under Wine. The
actual production PRX also passes 538 public cases, nine complete replays and
twelve null-pixel materialization cases. Native Windows GPU and iPad/game
qualification remain pending.

The iPad execution route remains:

```text
decrypted PS5 ELF → AnyPS5 ahead-of-time relinking → Windows program/HLE DLLs
                 → Wine + FEX → Vulkan → MoltenVK → Metal
```

The relinker prepares the Windows binary before execution; FEX translates its
x86-64 CPU code at runtime. These graphics changes affect the AnyPS5 Vulkan
implementation reached through Wine. They do not replace that route with a
native macOS runner or an ARM64 ahead-of-time CPU compiler. Madeira's library
and menu remain the launcher. Private game assets and raw diagnostics stay
outside Git; builds and tests run locally without GitHub Actions.

## Compute LDS beyond the device limit: #1776

[Upstream #1776](https://github.com/boykopovar/AnyPS5/pull/1776), merged as
`b75021141299f0ff038a7ef344583d969f8f39f5`, is reproduced by
[`0066-compute-lds-device-memory.patch`](../patches/anyps5/0066-compute-lds-device-memory.patch).

The compiler compares requested LDS bytes plus its synchronization word with
`maxComputeSharedMemorySize`. If that would exceed the actual device limit,
the SPIR-V program uses a coherent storage buffer at descriptor set 1. Each
workgroup receives its own LDS-plus-one-word slice, indexed using the linear
workgroup ID. Existing address bounds and zero results for out-of-range reads
remain in force; barriers and atomics use the corresponding storage-buffer
memory semantics with workgroup synchronization.

Dispatch allocates or grows the backing buffer in one-MiB granules, validates
the total group range against `maxStorageBufferRange`, and retains the buffer
and descriptor pool through the recorder. Existing dispatch barriers protect
reuse; replaced allocations survive pending GPU work. Indirect dispatch reads
group counts on the CPU when needed to size the backing allocation, reporting
reason 8. Compiler materialization and result serialization retain the slice
stride. The ordinary within-limit LDS path remains available.

The exact upstream execution regression is retained. It covers wave32,
wave64, split wave64, 2D/3D group indexing, direct/indirect dispatch, atomics,
barriers, out-of-range reads and untouched output regions. Compatibility for
large LDS is the intended result; storage-buffer spill can cost performance.
No MiniGolf speedup or device result is claimed.

## Complete storage-buffer array updates: #1831

[Upstream #1831](https://github.com/boykopovar/AnyPS5/pull/1831), merged as
`b23bd7323f994fe4455fd6671a8f6f9a9c49a7a8`, is reproduced by
[`0067-descriptor-array-snapshots.patch`](../patches/anyps5/0067-descriptor-array-snapshots.patch).

An immutable draw snapshot previously replaced individual descriptor-array
elements. The workaround writes each affected array from element zero in one
operation, avoiding the [MoltenVK partial-array update issue](https://github.com/KhronosGroup/MoltenVK/issues/2650).
Initial descriptors are saved so untouched elements retain their original
buffer handle, offset and range. Changed elements use the captured snapshot's
buffer and size. Descriptor-info storage is reserved before pointers are
published, and recorder ownership keeps snapshots alive through execution.

The initial descriptor-copy path and the existing explicit replay mode both
remain. The regression checks first-element, second-element and both-element
replacement, unrelated bindings, captured bytes and resource cleanup. Run
`agc_driver_graphics_tests --descriptor-snapshots-only` in fresh processes with
the default environment and with `APS5_EXPLICIT_DRAW_DESCRIPTORS=1`. Mock
descriptor correctness is distinct from actual MoltenVK rendering.

## Explicit typed image fallback: unmerged #2015

[Upstream #2015](https://github.com/boykopovar/AnyPS5/pull/2015), head
`b288aa84eca4ebfce7000f741e32b7d65c865e34`, remains an unmerged change. Its useful
typed-image implementation is integrated locally by
[`0068-typed-null-image-placeholders.patch`](../patches/anyps5/0068-typed-null-image-placeholders.patch),
with stricter device and policy contracts:

| Policy | Required behavior |
|---|---|
| `RequiresValidImages=0` | Missing guest images and zero Vulkan views fail before descriptor publication. |
| `NativeNull=1` | Null views require the actually enabled robustness2 `nullDescriptor` feature. |
| `TypedPlaceholders=2` | An explicit host fallback supplies real typed image views; it never fabricates native-null support. |

The ordinary profile constructor remains conservative; the Vulkan device
explicitly selects the fallback when native null descriptors are unavailable.
An immutable profile and the graphics context must agree on that capability.
Request version 15, full/interface/memo keys and disk schema 22 distinguish all
three policies. Old version14 requests remain conservative. Changed compiler
sources produce a new source-derived cache identity; old caches are not reused
as new payloads.

Up to 56 typed heaps cover dimension, numeric class, access and comparison
variants. The provider checks exact format, image type, usage, sample count,
limits and enabled storage-multisample, portability-array and 64-bit atomic
features. Unsupported heaps remain absent and fail on first use. Supported
images are allocated, bound, viewed, transitioned, cleared to zero and moved
to GENERAL; initialization completes before publication. Partial failures and
teardown release views, images and memory in that order.

These are 1×1×1, one-layer images, with four samples for multisample heaps.
Image-size/sample queries, comparison sampling, out-of-range behavior, storage
writes and atomics therefore do not acquire Vulkan native-null semantics.
Storage descriptors in a heap alias the same placeholder; writes can survive
later draws. The fallback requires per-title rendering qualification. A DOOM
report on macOS does not establish MiniGolf or iPad compatibility.
